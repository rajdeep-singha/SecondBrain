**claude:** Yes, it relates — but pyros sits on the *opposite side* of the exact tension RoboMorph illustrates. Worth being precise about that, because it's the interesting part.

## What RoboMorph is doing

RoboMorph puts the LLM *inside* the optimization loop as the variation operator:

- LLM proposes body plans (constrained by a grammar so outputs stay valid)
- each candidate gets an RL controller trained in sim → fitness score
- top performers go back into the prompt → next generation

The LLM is a *learned prior over "plausible good mutations."* It beats classical graph/tree search because graph search explores a combinatorial space blindly, while the LLM has absorbed structural intuitions about what morphologies tend to work. That's the whole thesis: an informed mutation operator prunes a huge space that BFS/DFS/evolutionary-random never reaches efficiently.

## How pyros overlaps

Genuine shared DNA:

- **Grammar-constrained generation.** RoboMorph's grammar ≈ pyros's `design-arm` / URDF generation writing *valid, dynamics-ready* structures instead of free-form text. Both refuse to let the model emit garbage.
- **Sim in the loop.** pyros has a MuJoCo backend (`src/pyros/sim/`), vendor CAD, real robot poses — the same substrate you'd score candidates in.
- **Robot morphology as a first-class object.** pyros already reasons over kinematic chains, Jacobians, reachable workspace — exactly the fitness signals (reach, manipulability, dexterity) an evolutionary loop would optimize.

So the *machinery* pyros has built (a valid-URDF generator + a MuJoCo scorer + deterministic morphology metrics) is essentially the evaluation half of a RoboMorph loop.

## Where pyros deliberately diverges

This is the part I'd flag rather than paper over. pyros's founding claim is: **"Every number came from a tool, not the model's memory."** The LLM is the *orchestrator*, and the engineering is *deterministic and cited*. RoboMorph does the reverse — it puts the LLM's intuition on the critical path as the generative engine and trusts emergent, un-cited morphologies precisely *because* "classical search never found them."

Those are two different bets:

| | pyros | RoboMorph |
|---|---|---|
| LLM's job | orchestrate cited, reproducible tools | *be* the mutation operator |
| Trust source | datasheet catalog + textbook citation | RL fitness in sim |
| Output you defend to an engineer | "Spong §8.2, margin 92%" | "it converged here, empirically" |

## The actually-interesting synthesis

RoboMorph's weak spot is exactly pyros's strength. An LLM-evolved morphology is unaccountable — you can't hand it to a robotics engineer and justify the link lengths. pyros could be the **fitness function and the accountability layer** for such a loop: let an evolutionary search propose bodies, but score each with pyros's deterministic `analyze_workspace` / `compute_dynamics` / `size_actuator`, so the winning design arrives *with* its torque budget, singularity map, and a real motor that can drive it — not just a sim reward number.

That's a real feature direction, if you want it: `pyros evolve-morphology` — grammar-constrained body proposals, pyros metrics as fitness, cited spec sheet on the survivor. It's the honest version of RoboMorph.
