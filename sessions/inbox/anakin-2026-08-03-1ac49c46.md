## 1. Proxy latency EMA never seeds the first sample (clear bug)
`server/internal/proxy/pool.go:132-134`

```go
if latencyMs > 0 {
    sc.AvgLatencyMs = int(float64(sc.AvgLatencyMs)*(1-latencyEMA) + float64(latencyMs)*latencyEMA)
}
```

On a proxy's **first** success, `AvgLatencyMs` is `0`, so a 1000ms request gets recorded as `0*0.8 + 1000*0.2 = 200ms`. The EMA never initializes with a real value, so latency is permanently under-reported (and surfaced wrong in `/v1/proxy/scores`).

**Fix:** seed on first sample —
```go
if latencyMs > 0 {
    if sc.AvgLatencyMs == 0 {
        sc.AvgLatencyMs = latencyMs
    } else {
        sc.AvgLatencyMs = int(float64(sc.AvgLatencyMs)*(1-latencyEMA) + float64(latencyMs)*latencyEMA)
    }
}
```

## 2. `Pool.Submit` blocks the HTTP request under load, despite its doc
`server/internal/worker/worker.go:59-62`

```go
// Submit adds a job to the pool. Non-blocking if buffer has space.
func (p *Pool) Submit(msg models.JobMessage) {
    p.jobs <- msg
}
```

The comment implies non-blocking, but when the buffer fills, `p.jobs <- msg` blocks. It's called **synchronously inside the request handlers** (`CreateJob`, `ScrapeSync`, and in a loop in `CreateBatchJob`), with no context, so a saturated pool makes API requests hang indefinitely. Either make it truly non-blocking with a `select { case p.jobs <- msg: ... default: return ErrPoolFull }` and return 503, or at minimum fix the misleading comment.

## 3. Gemini truncated-JSON repair runs twice
`server/internal/gemini/client.go:327-330` then again at `:348-350` / chunk paths (`:157-159`, `:212-214`)

`callGeminiAPI` already calls `repairTruncatedJSON(jsonText)` when `wasTruncated`, then returns `wasTruncated=true`, so every caller (`validateAndFormatJSON`, both chunk loops) repairs the *same* string a second time. Harmless but wasteful and confusing. Pick one place to repair — either drop it from `callGeminiAPI` or from the callers.

## 4. Dangling backslash in `sanitizeInvalidEscapes`
`server/internal/gemini/client.go:383-428`

When a string ends with a lone `\` at EOF (`i+1 >= len`), the `ch == '\\'` branch is skipped and the trailing backslash is written verbatim, producing invalid JSON. A trailing-backslash guard fixes it. (Edge case, only on truncated output — low priority but real.)

## 5. Batch reports `completed` even when every child failed
`server/internal/http/handlers/scraper.go:354-361`, and the persisted version in `store/postgres.go:156` + `store/memory.go:135`

The derived/persisted batch status only distinguishes pending/processing; once nothing is pending or processing it's `completed`, regardless of whether all children *failed*. Depending on intent this may be by design ("all done"), but if you want a `failed`/`partial` state it's a small, contained change in these three spots. Flagging as debatable, not a definite bug.
