**Why this happened:** my original SQL enabled RLS and added an insert *policy*, but a policy only controls *which rows* a role may write. The role also needs the table-level `GRANT`. Tables made through the dashboard Table Editor get these grants automatically; ones created via raw SQL don't always, which is why the anon key hit "permission denied." I've added the `grant` line to `job_applications.sql` so a fresh setup won't have this issue.

One thing worth confirming: the anon key is public (it ships in the frontend bundle), so make sure the table has **no `SELECT` policy** — otherwise anyone could read all applicants' data. My SQL intentionally omits it, so reads are blocked; view submissions in the Table Editor. Just don't add a select policy later without meaning to.
